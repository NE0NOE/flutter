# AI Script Import Schema & Guidelines

wger Flutter supports importing complete workout routines and nutrition plans directly from text scripts generated by Large Language Models (ChatGPT, Claude, Gemini, etc.) or exported from other tools.

The importer parses JSON with exact source line and column tracking, validates all references locally against the on-device Drift database, presents an interactive preview with full counts, and writes all records transactionally to local storage so it functions completely offline without requiring an active server connection. Upon saving, routine media prefetching is dispatched in the background to ensure all exercise GIFs, images, and videos are immediately cached for offline gym use.

---

## Specification: Versioned Schema

Every script must define the integer root field `"schema_version"`.

- **Current Version:** `1`
- **Extensibility Policy:**
  - Unknown root or child fields generate non-fatal **warnings** and are ignored, allowing future optional enhancements without breaking backwards compatibility.
  - Scripts with unsupported schema versions (`schema_version > 1` or `< 1`) are rejected with a clear error identifying the exact line and supported versions.

### Full Schema Structure (Version 1)

```json

  "schema_version": 1,
  "meta": {
    "description": "Optional script notes or AI generator metadata"
  },
  "routines": [
    {
      "action": "create", // "create" (default) or "update"
      "id": 123, // Integer ID, required if action is "update" without unique name
      "name": "Upper / Lower Split", // Required, 1-25 characters
      "description": "4-day strength routine", // Optional, max 1000 characters
      "start": "2026-11-11", // Optional start date (YYYY-MM-DD), defaults to current date
      "end": "2027-02-03", // Optional end date (YYYY-MM-DD), defaults to start + 12 weeks
      "fit_in_week": true, // Optional boolean
      "days": [
        {
          "name": "Upper Power", // Required, 1-20 characters
          "description": "Chest, Back, Arms", // Optional
          "day_type": "custom", // Optional: custom, enom, amrap, hiit, tabata, edt, rft, afap
          "is_rest": false, // Optional boolean
          "order": 1, // Optional ordering index
          "slots": [
            {
              "order": 1, // Optional slot order
              "comment": "Main compound lift", // Optional notes
              "alarm": 120, // Optional rest timer in seconds
              "exercises": [
                {
                  "exercise": "Bench Press", // Required: Exercise name, integer ID, or UUID
                  "sets": 4, // Required: Integer >= 1
                  "reps": 6, // Required: Repetitions number > 0
                  "repetition_unit": "reps", // Optional unit: "reps", "sec", etc.
                  "weight": 80.0, // Optional recommended weight
                  "weight_unit": "kg", // Optional: "kg" or "lb"
                  "rest_time": 120, // Optional rest time in seconds
                  "rir": 2.0, // Optional Reps in Reserve (0.0 to 4.5 in steps of 0.5)
                  "entry_type": "normal", // Optional: normal, warmup, dropset, myo
                  "alarms": true, // Optional boolean

                }

            }
          ]
        }
      ]
    }
  ],

    {
      "action": "create", // "create" (default) or "update"

      "description": "High Protein Muscle Building Plan", // Required plan name
      "start": "2026-11-11", // Optional start date (YYYY-MM-DD)

              "unit": "g", // Optional unit name

            }
          ]
        }
      ]
```

## Entity Resolution & Update Behavior

1. **Exercise Matching:**
   - Case-insensitive search on local exercise name, exact integer ID, or UUID.
   - If an exercise name cannot be matched against local catalog data, the importer flags an actionable error specifying the line number, field path (e.g. `routines[0].days[0].slots[0].exercises[0].exercise`), and the unmatched string.
2. **Ingredient Matching:**
   - Case-insensitive search on local ingredient name, exact integer ID, or UUID.
   - Unknown ingredients are flagged with line and field path before database persistence.
3. **Create vs. Update:**
   - `action: "create"` (or omitted): Appends new routines and nutrition plans with generated local IDs and UUIDs.
   - `action: "update"`: Modifies existing entries. Requires `id` (integer for routines, UUID string for nutrition plans) or matches an existing unique title.
